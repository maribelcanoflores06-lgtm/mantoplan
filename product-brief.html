⚙️ MantoPlan

Gestión de mantenimiento · Planta textil (Perú) · Área de Mantenimiento — hilandería, preparación y tejeduría

📍 Situación actual

La planner programa el mantenimiento en un sistema antiguo y en hojas de cálculo. No tiene visibilidad de componentes y subcomponentes por máquina, ni de repuestos y su stock; el historial de cambios está disperso y los quiebres de stock se detectan tarde.

1. Problema

  • Sin trazabilidad de qué repuesto se cambió, en qué máquina y cuándo.
  • Stock desactualizado → paradas por falta de repuestos o sobrecompras.
  • Tiempo perdido consolidando Excel para planificar.

2. Usuario

Principal: planner / programadora de mantenimiento.
Secundarios: técnicos (registran cambios) y jefe de mantenimiento (consulta KPIs y decide compras).

3. Funcionalidades

  • Dashboard con KPIs: máquinas, repuestos con stock bajo, cambios del mes.
  • Árbol Máquina → Componente → Subcomponente → Repuestos.
  • Repuestos con stock y stock mínimo, con alerta visual.
  • Registro de cambio de repuesto con validaciones: descuenta stock y guarda en historial (mensaje verde/rojo).
  • Historial con filtros por máquina, fechas y técnico/repuesto.

4. Datos e IA

Máquinaid, código, nombre, áreaComponenteid, máquina_id, nombre
Subcomponenteid, componente_id, nombreRepuestoid, código, nombre, subcomponente_id, stock, stock_mínimo
Cambio / Historialid, fecha, repuesto_id, cantidad, técnico, observación
IA: predecir el consumo de repuestos según el historial y alertar antes del stock bajo; sugerir mantenimiento preventivo por máquina según la frecuencia de cambios.

📝 Historias de usuario

HU1. Como planner quiero ver los repuestos con stock bajo para pedirlos antes de que paren las máquinas. CA: se marca en rojo cuando stock ≤ mínimo; el dashboard muestra el total.
HU2. Como técnico quiero registrar el cambio de un repuesto para que quede en el historial. CA: cantidad entera > 0, fecha no futura, técnico obligatorio; descuenta stock; mensaje verde al guardar y rojo si falla o no hay stock.
HU3. Como planner quiero ver la estructura de cada máquina para saber qué repuestos usa cada subcomponente. CA: árbol desplegable máquina → componente → subcomponente con código y stock.
HU4. Como jefe de mantenimiento quiero filtrar el historial por máquina y fechas para analizar fallas recurrentes. CA: filtros combinables; "Sin resultados" si no hay coincidencias.

🧰 Stack y arquitectura

HTML + CSS + JavaScript vanilla · Supabase (PostgreSQL, RLS, función registrar_cambio) · Modo demo con localStorage · Hosting estático en Vercel / GitHub Pages. Agente de Cursor/Antigravity con reglas en .agents/rules.

📈 Métricas de éxito

  • 100% de cambios registrados en la app (0 Excel)
  • −50% de quiebres de stock en 3 meses
  • Registrar un cambio en < 1 minuto
